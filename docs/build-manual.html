Scope note. Everything below is verbatim and complete, with one deliberate exception: the sqlc-generated files under internal/db/ and the boilerplate the SvelteKit CLI writes (app.html, app.d.ts, tsconfig.json, favicon.svg). Those are produced by tools you will run in steps 06 and 08 — typing them by hand would be wrong, and they get overwritten anyway.

Step 07 shows the original response layer, which has since been replaced. The handlers below write {"error": "some string"} and choose their own status codes. The project now envelopes every response as {data, meta} / {error:{kind,message,code,fields}, meta}, and handlers return a typed error that a single map turns into a status.

Everything else here — the layout, the toolchain, the sqlc loop, the migrations, the task runner — is current. For the response layer, the Day 1 Closeout change log carries the replacement in full: internal/httpx, the typed error set, the config gate, and cmd/migrate.

02

Folder and git identity

Create the repo and pin the author to this project only.

Now set the author locally. Every command here omits --global on purpose:

Why local, not global. If you already have a git identity for a different account on this machine, a --global setting here would silently re-author your other projects' commits. Local config lives in .git/config and applies to this folder alone. Confirm with git config user.email run from inside the folder.

core.autocrlf input stops Windows CRLF line endings from being committed, which otherwise shows up as a whole-file diff the first time a colleague on macOS or Linux touches it.

03

Root configuration files

Four files that decide what gets committed and how config flows.

Two patterns here are doing real work. .env then !.env.example ignores every environment file except the committed template — order matters, the negation must come after the rule it reverses. The .vscode/* block does the same thing: ignore the folder's contents, then re-admit the four files a team actually benefits from sharing, while leaving your personal editor state out.

Note .vscode/* with a trailing /* rather than .vscode/. Git cannot re-include a file inside a directory it has already excluded, so ignoring the contents instead of the directory is what makes the four negations work at all.

Go is gofmt-formatted with tabs; everything else uses two spaces. Encoding this here means the editor obeys without anyone having to remember.

Pick a host port no other stack owns — and check, do not assume. 5432 is the Postgres default, so the first database on your machine takes it and the second fails to bind. But the next port up is not automatically safe either: on this machine 5432 belongs to a host Postgres and 5433 to another project's container, which is why office360 sits on 5434. Run docker ps and Test-NetConnection localhost -Port <n> before choosing. If you change it, change it in three places: POSTGRES_PORT, the host half of DATABASE_URL, and the default in docker-compose.yml.

04

The database container

One Postgres 16 service with a health check the task runner can wait on.

The health check earns its place. docker compose up -d returns as soon as the container starts, but Postgres needs several more seconds before it accepts connections. Without healthcheck, the migration in step 12 races the database and fails perhaps one run in three. The task runner polls this field instead of sleeping a fixed number of seconds.

Both container_name and the named volume are prefixed with the project. Compose derives default names from the folder, and two projects in similarly-named folders can collide.

05

Go module and dependencies

Initialise the module under your GitHub path and pull five libraries.

The module lives at the repository root, not in a subdirectory. Go source goes in cmd/ and internal/; api/ is reserved for API specifications. Nesting the module under api/ works, but then every import path carries an extra segment and no external instruction that names internal/… lines up with your tree.

The module path must match the repo. github.com/<user>/<repo> is what every internal import in step 07 is written against. Get it wrong now and you will be rewriting import lines across a dozen files later.

On Go 1.27, go mod edit -go=1.23.0 is rejected — the equals form fails with invalid -go option. Use the space-separated form shown above. This pins the language version to 1.23 while still building with whatever newer toolchain you have installed.

Create the directory skeleton now so the files in the next two steps have somewhere to land:

Create every directory now, including the ones you will not fill for days. internal/platform (auth, tenancy) and internal/modules (business domains) stay empty for a while — but a tree that never changes shape is one fewer thing to reorganise later, and git will track them once each holds a README.

06

Schema, queries, sqlc

Write SQL; let sqlc compile it into type-safe Go.

This is the part of the stack most likely to confuse you later, so understand the model before writing anything: sqlc reads your migrations as the schema and your query files as the queries, then generates Go. It never touches a running database. That means a query naming a column you have not yet written a migration for will fail to generate — the migrations are the source of truth, not your local Postgres.

Migrations

Always write the .down.sql. golang-migrate pairs files by number and refuses to roll back without one. Drop in reverse dependency order — employees references departments, so it goes first.

Queries

Do not mix $1 positional parameters with sqlc.arg() in the same query. sqlc numbers them independently and you get a generated struct whose field order silently disagrees with the SQL. Pick named parameters and stay with them; arg is required, narg is nullable.

Cast every named parameter — ::uuid, ::text, ::date. Postgres cannot infer the type of a bare placeholder inside coalesce() or on the null side of an IS NULL OR, and sqlc surfaces that as an unhelpful generation error.

The coalesce(narg, column) pattern in UpdateEmployee is what makes PATCH partial: omit a field in JSON, it arrives as Go nil, and the column keeps its existing value.

sqlc configuration

The overrides block is the difference between clean JSON and unusable JSON. Left alone, the pgx/v5 driver maps uuid to pgtype.UUID and timestamptz to pgtype.Timestamptz — wrapper structs that serialise as nested objects like {"Time":"…","Valid":true}. Mapping them to uuid.UUID and time.Time, with emit_pointers_for_null_types turning nullable columns into *string / *time.Time, gives you plain strings and honest nulls that a TypeScript client can consume directly.

emit_empty_slices is a smaller kindness: list queries return [] instead of null when nothing matches, so the front end never has to null-check before mapping.

This writes four files into internal/db/: db.go, models.go, departments.sql.go, employees.sql.go. They are generated output — commit them, but never edit them, because the next sqlc generate discards your changes without warning.

07

The Go server

Six hand-written files: config, response helpers, router, and handlers.

The three-path loop is load-bearing. godotenv.Load() given several filenames at once aborts at the first one that does not exist, so passing ".env", "../.env" in a single call silently skips the root file whenever you run from api/. Loading each separately, and relying on godotenv never overwriting an already-set variable, makes the server work from either directory.

DisallowUnknownFields turns typos into 400s. Without it, a client sending {"fullname":…} instead of {"full_name":…} gets a cheerful 201 and a record with an empty name. MaxBytesReader caps the body so a malicious or broken client cannot exhaust memory.

timePtr has a pointer receiver and checks d == nil deliberately — that makes it safe to call on an absent JSON field without a nil guard at every call site.

Mapping SQLSTATEs to 4xx is the single highest-value habit in this file. A duplicate email is the client's mistake, not the server's — returning 409 rather than a 500 tells the caller something actionable and keeps genuine 500s meaningful in your logs. The three codes worth handling almost everywhere are 23505 unique, 23503 foreign key, and 23514 check constraint.

Note the ordering trap in updateEmployee: the pgx.ErrNoRows check must come before the constraint check, because an update targeting a missing id is a 404, not a 400.

Ping before serving. pgxpool.New is lazy — it validates the URL but opens no connection, so without the explicit Ping a server with a wrong password starts happily and fails on the first request instead of at boot, where you would actually notice.

The shutdown context is deliberately built from context.Background(), not ctx. By the time you reach that line ctx is already cancelled by the signal, so deriving from it would give Shutdown zero time to drain in-flight requests.

Checkpoint. Both commands should print nothing at all. Silence is success.

08

The SvelteKit app

Scaffold with the official CLI, then add a typed client and one page.

Those flags matter — sv create is interactive by default and will sit waiting for keystrokes without them. Then change the project name in web/package.json from "web" to something meaningful like "office360-web".

envDir: '..' is what collapses two .env files into one. Vite loads environment files relative to its own root, which is web/ — so by default your PUBLIC_API_URL at the repo root is invisible to the front end. Pointing envDir one level up means a single file at the root configures both halves of the stack.

Why $env/dynamic/public and not static. The static variant is inlined at build time and throws outright if the variable is missing, which breaks a fresh clone before anyone has copied .env.example. Dynamic reads at runtime and lets the ?? 'http://localhost:8080' fallback do its job.

Threading fetch through every call is a SvelteKit requirement, not a style choice. During server-side rendering, the framework passes load an instrumented fetch; using the global one instead loses relative-URL resolution and request deduplication.

Then the page itself — a load function that survives the API being down, and a table:

Catching in load is a deliberate first-run affordance. Letting the error propagate gives a new contributor a SvelteKit error page with a stack trace; catching it gives them the dashboard plus the exact command to start the missing API.

The remaining two view files — web/src/app.css and web/src/routes/+page.svelte, plus a small nav wrapper in +layout.svelte — are ordinary presentation code with no scaffolding decisions embedded in them. Copy them from the repo, or write your own; nothing later in this manual depends on their contents.

Checkpoint. Expect 0 ERRORS 0 WARNINGS.

09

Task runner and VS Code

One script that knows every command, wired to the editor.

Windows has no make, so this project uses a PowerShell script instead. Its real job is loading .env into the process before each task — that is what guarantees migrate, psql, and the API all agree on which database they are talking to.

ValidateSet gives you tab-completion for free — type .\make.ps1 and press Tab to cycle the available tasks. It also turns a typo into an immediate clear error rather than a silently skipped switch.

Every task uses Push-Location/Pop-Location in a try/finally so that interrupting make.ps1 api with Ctrl-C does not leave your shell stranded in api/.

Editor configuration

The -ExecutionPolicy Bypass in tasks.json avoids a common Windows dead end — the default policy blocks unsigned local scripts, so tasks would fail with a security error on a fresh machine. Setting it per-invocation keeps the machine-wide policy untouched.

envFile in launch.json is why the debugger can reach the database: without it, F5 starts the binary with no DATABASE_URL and it exits immediately.

10

Project documentation

A README for humans, a CLAUDE.md for AI tooling.

Write README.md covering the stack table, the directory layout, prerequisites, the first-run sequence, the task table, and the API route table.

Then CLAUDE.md at the repo root, which Claude Code reads automatically when a session opens in this folder. Keep it to what is non-obvious — do not restate what the code already shows. For this stack that means:

  • The sqlc loop and its ordering constraint (migration first, then query, then generate)
  • That internal/db/ is generated and hand-edits are silently reverted
  • The SQLSTATE-to-4xx convention and where the pattern lives
  • Why the host port is 5434 — so nobody "fixes" it back into a collision
  • The single root .env and the envDir: '..' wiring
  • That git identity is per-repo here and must not move to --global
  • Which command is the real gate before calling work done (./make.ps1 check)

A per-project CLAUDE.md matters more than it looks. Without one, a session opened in this folder can inherit conventions from a different project — including instructions to use MCP tools or knowledge graphs that do not exist here. An empty-but-accurate file beats an absent one.

11

Connect to GitHub

Commit, attach the remote, reconcile with whatever GitHub created.

Read that list before committing. You should see roughly 45 files and not see node_modules, .env, .svelte-kit, or package-lock.json from anywhere but web/. If a secret or a build artefact is in there, fix .gitignore now — removing it after the first push is far more work.

Put the username in the remote URL. Windows Credential Manager keys stored credentials by host — so a plain https://github.com/… remote will reuse whatever GitHub token is already saved, which is the wrong account if you have more than one. Embedding user@ makes the credential entry account-specific and keeps two identities on one machine from colliding.

Now check whether the remote is genuinely empty. If you ticked "Add a README" when creating the repo, it is not, and a plain push will be rejected:

Any output means the remote already has commits. Fetch, inspect what is actually there, and rebase your work on top of it:

GitHub's auto-generated README.md will collide with yours. Resolve in favour of your version and continue:

During a rebase, --theirs means your commit. This reverses the intuition: git is replaying your work onto the upstream branch, so "ours" is origin/main and "theirs" is the commit being applied. Reach for --ours here and you will silently keep GitHub's one-line placeholder and discard your README.

Rebase rather than force-push. git push --force would work too, but it destroys the remote's commit — fine for a placeholder, disastrous if you misread the situation and someone else's work was there.

Credential Manager opens a window on the first push. Choose Sign in with your browser and authenticate as the account that owns the repo — simpler than a token and it does not expire. If you prefer a Personal Access Token, it needs Contents: Read and write on this repository.

Confirm that prints the identity you set in step 02, not your other account.

Reusing this for a new project

Everything above generalises. Here is what actually changes per project, and what is safe to copy untouched.

FileWhat to change
.gitignoreNothing — copy as is.
.editorconfigNothing — copy as is.
.env.exampleDatabase name, user, password, and a host port no other stack owns.
docker-compose.ymlcontainer_name, the volume name, and the default port. Three edits.
go.modModule path — github.com/<user>/<repo>/api.
Go importsEvery internal/ import line follows the module path. Find-and-replace once, early.
sqlc.yamlNothing — the overrides are stack-level, not project-level.
internal/db/Everything. This is your actual domain.
internal/httpapi/respond.go and server.go's skeleton carry over; handlers are per-domain.

README.md / CLAUDE.mdRewrite for the new domain.

The short version

  1. Copy the whole folder, delete .git, node_modules, .svelte-kit, and internal/db.
  2. git init -b main and set the local identity (step 02).
  3. Find-and-replace the module path and the project name across the tree.
  4. Replace internal/db/migrations and internal/db/query with your own domain.
  5. sqlc generate, then write handlers against whatever it produced.
  6. Point web/src/lib/types.ts at the new shapes.
  7. ./make.ps1 check, commit, attach the remote, push.

Traps worth knowing

Each of these costs an hour if you meet it without warning.

SymptomCause and fix
sqlc errors on a column that exists It reads migrations, not your live database. Write the migration file first; applying it is a separate step.
Generated struct fields in the wrong order $1 mixed with sqlc.arg() in one query. Use named parameters throughout.
sqlc cannot infer a parameter type Add an explicit cast — sqlc.narg('x')::text.
Your edits to internal/db vanished It is generated. Change the .sql file and regenerate.
JSON full of {"Valid":true} wrappers Missing type overrides in sqlc.yaml.
migrate: unknown driver postgres Installed without -tags 'postgres'. Reinstall with it.
bind: address already in use Another Postgres owns that port. Check with docker ps — on this machine 5432 and 5433 were both taken, so office360 uses 5434.
API starts, dies on first request pgxpool.New connects lazily. The explicit Ping at boot is what surfaces it.
Migration fails right after up Racing the container. Wait on the health check, not a fixed sleep.
PUBLIC_API_URL undefined in the browser Vite loads env from web/. Set envDir: '..'.
CORS error in the browser console The dev origin is missing from CORS_ORIGINS.
Commits attributed to the wrong account Identity set globally. Set it per-repo and put the username in the remote URL.
Push rejected, non-fast-forward GitHub created a README. Fetch and rebase; take --theirs on the conflict.
go mod edit -go=1.23.0 rejected Go 1.27 wants the space form: go mod edit -go 1.23.0.
sv create hangs Interactive by default. Pass --template, --types, --no-add-ons, --install.
VS Code task: script not digitally signed Execution policy. tasks.json passes -ExecutionPolicy Bypass per invocation.
