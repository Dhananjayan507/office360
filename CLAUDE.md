# CLAUDE.md

Guidance for Claude Code (claude.ai/code) when working in this repository.

## What this is

A multi-tenant ERP for Indian business operations, built to a 14-day structural
plan. Three portals — Super Admin (`/platform`), Admin (`/app`), Client
(`/portal`) — over one Go API and one Postgres database.

**Currently at the end of Day 1.** The server foundation exists; multi-tenancy,
auth and every business module do not. Do not build features on the current
single-tenant schema — Day 2 adds `organization_id` to every business table.

## Commands

All tasks go through `make.ps1` at the repo root (PowerShell — this is a Windows-first repo).

```bash
./make.ps1 up          # start Postgres 16 in Docker, wait for healthy
./make.ps1 down        # stop it (data preserved)
./make.ps1 nuke        # stop AND delete the volume — DESTROYS local data, prompts first
./make.ps1 migrate     # apply pending migrations (runs ./cmd/migrate)
./make.ps1 rollback    # roll back the last migration
./make.ps1 sqlc        # regenerate internal/db
./make.ps1 api         # run the Go API (blocks)
./make.ps1 web         # run the SvelteKit dev server (blocks)
./make.ps1 check       # go build + go vet + svelte-check — the gate before calling work done
./make.ps1 psql        # psql shell inside the container
```

`make.ps1` sources the root `.env` into the process before every task, so
`migrate` and `psql` always agree with what the API will connect to.

There is no test suite yet. `./make.ps1 check` is currently the only automated
gate — it compiles and type-checks, but proves nothing about behaviour.

## Architecture

The Go module is rooted at the **repository root**. `api/` holds API
specifications, not Go source — do not put `.go` files there.

```
cmd/server/        main() — config → pgxpool → chi router → graceful shutdown
cmd/migrate/       migration CLI, so golang-migrate need not be installed
internal/config/   env loading; refuses to start on bad config
internal/httpx/    envelopes, typed errors, request logging   ← response shaping
internal/httpapi/  router + handlers                          ← write handlers here
internal/platform/ auth, authz, tenant, audit                 (Day 3–4, empty)
internal/modules/  one directory per business domain          (Day 6+, empty)
internal/db/       GENERATED by sqlc — never hand-edit
internal/db/migrations/  golang-migrate .up/.down pairs  ← schema source of truth
internal/db/query/       hand-written SQL               ← input to sqlc
web/src/lib/api.ts       typed client
web/src/lib/types.ts     TS mirrors of the Go JSON shapes
```

### Response envelopes — the rule that matters most

**Handlers never choose a status code.** They return a typed error from
`internal/httpx`, and `statusByKind` in `httpx/errors.go` is the single place a
status is decided. Handlers have signature `func(w, r) error` and are wrapped
with `httpx.Handle(...)` when routed.

Every response is enveloped: `{data, meta}` on success,
`{error:{kind,message,code,fields}, meta}` on failure. `meta.request_id` is
always present; `total`/`limit`/`offset` appear on lists.

Kinds map as: validation 400, unauthenticated 401, forbidden 403, not_found 404,
method_not_allowed 405, conflict 409, rule_violation 422, rate_limited 429,
internal 500. Anything that is not a `*httpx.Error` becomes `internal`, so a raw
pgx or json error can never reach a client.

`Code` is a stable machine-readable string (`employee.email_taken`) — clients
branch on that, not on prose. `Fields` carries per-field validation messages.

The one documented exception is `/healthz`, which calls `httpx.Write` with an
explicit 200 or 503, because there the status *is* the answer.

### The sqlc loop (the thing that surprises people)

sqlc reads `internal/db/migrations/` as the schema and `internal/db/query/` as
the queries. **A query referencing a column you have not yet written a migration
for will fail to generate**, and a migration alone changes nothing until you
regenerate. Order:

1. New migration pair in `internal/db/migrations/`.
2. Add/edit queries in `internal/db/query/`.
3. `./make.ps1 sqlc`.
4. `./make.ps1 migrate`.
5. Handlers, routes wired in `internal/httpapi/server.go`.
6. Mirror the JSON shape in `web/src/lib/types.ts`, add a call in `web/src/lib/api.ts`.

`sqlc.yaml` overrides `uuid` → `github.com/google/uuid.UUID`, `timestamptz`/`date`
→ `time.Time`, with `emit_pointers_for_null_types`. Nullable columns are Go
pointers and marshal to JSON `null` rather than pgtype wrapper objects. Keep new
overrides consistent.

Prefer `sqlc.arg('name')` / `sqlc.narg('name')` over `$1`, and cast them
(`sqlc.narg('status')::text`). Mixing named and positional params in one query
produces confusing generated argument ordering.

### Config

One `.env` at the repo root serves both apps — the Go side via godotenv, the web
side because `vite.config.ts` sets `envDir: '..'`. Adding a variable means adding
it to `.env.example` too.

The server **refuses to start** without `DATABASE_URL`, or without a
`JWT_SECRET` of at least 32 characters. There is no fallback: a server without a
signing key accepts forged tokens.

## Gotchas

- **Postgres binds host port 5434, not 5432.** Deliberate: Docker Desktop on this
  machine is shared with the ebike stack, whose container owns 5433, and a host
  Postgres already holds 5432. Do not "fix" this back to a lower port.
- **Keep `make.ps1` pure ASCII.** PowerShell 5.1 reads `.ps1` as Windows-1252
  unless there is a BOM, and a UTF-8 em dash decodes into a smart quote that
  silently unbalances every string after it.
- The generated `.go` files in `internal/db/` are regenerated by
  `./make.ps1 sqlc`; hand-edits are silently reverted. The `migrations/` and
  `query/` subdirectories are yours.
- `./make.ps1 nuke` and `docker compose down -v` destroy the local volume.
- `hired_on` is a bare `YYYY-MM-DD` date. The `jsonDate` type in
  `internal/httpapi/types.go` exists because `time.Time` alone demands full
  RFC 3339 — reuse it for any new `date` column.
- Testing config failures is fiddly: setting `$env:JWT_SECRET = ""` in PowerShell
  makes the child process see it **unset**, and godotenv then loads the repo
  `.env`. Run the binary from a directory with no `.env` above it and use
  `Remove-Item env:JWT_SECRET`.
- New API areas need CORS to match — the browser origin must be in `CORS_ORIGINS`.
- Svelte 5 runes mode is forced for project files in `vite.config.ts` — use
  `$props()` / `$derived()`, not `export let`.
- The git identity here is set **per-repo** (`Dhananjayan507`), separate from the
  global identity. Don't move it to `--global`.
