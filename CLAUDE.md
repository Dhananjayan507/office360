# CLAUDE.md

Guidance for Claude Code (claude.ai/code) when working in this repository.

## Commands

All tasks go through `make.ps1` at the repo root (PowerShell — this is a Windows-first repo).

```bash
./make.ps1 up          # start Postgres 16 in Docker, wait for healthy
./make.ps1 down        # stop it (data preserved)
./make.ps1 nuke        # stop AND delete the volume — DESTROYS local data, prompts first
./make.ps1 migrate     # apply pending migrations
./make.ps1 rollback    # roll back the last migration
./make.ps1 sqlc        # regenerate api/internal/db
./make.ps1 api         # run the Go API (blocks)
./make.ps1 web         # run the SvelteKit dev server (blocks)
./make.ps1 check       # go build + go vet + svelte-check — the gate before calling work done
./make.ps1 psql        # psql shell inside the container
```

`make.ps1` sources the root `.env` into the process before every task, so
`migrate` and `psql` always agree with what the API will connect to.

There is no test suite yet. `./make.ps1 check` is currently the only automated gate.

## Architecture

Two deployables in one repo: a Go HTTP API and a SvelteKit web app, over one Postgres 16 database.

```
api/cmd/server/        main() — config → pgxpool → chi router → graceful shutdown
api/internal/config/   env loading (godotenv, optional .env)
api/internal/httpapi/  chi router + handlers          ← write handlers here
api/internal/db/       GENERATED by sqlc              ← never hand-edit
api/db/migrations/     golang-migrate .up/.down pairs ← schema source of truth
api/db/query/          hand-written SQL               ← input to sqlc
web/src/lib/api.ts     typed client for the Go API
web/src/lib/types.ts   TS mirrors of the Go JSON shapes
```

### Layering

`internal/httpapi/*.go` (HTTP concerns: parsing, validation, status codes) →
`internal/db` (sqlc-generated queries) → `pgxpool`. Handlers never build SQL;
all SQL lives in `api/db/query/*.sql` and is compiled by sqlc.

### The sqlc loop (the thing that surprises people)

sqlc reads `api/db/migrations/` as the schema and `api/db/query/` as the queries.
That means **a query referencing a column you have not yet written a migration
for will fail to generate**, and a migration alone changes nothing until you
regenerate. Order:

1. New migration pair in `api/db/migrations/` (`000002_thing.up.sql` + `.down.sql`).
2. Add/edit queries in `api/db/query/`.
3. `./make.ps1 sqlc` — regenerates `api/internal/db`.
4. `./make.ps1 migrate` — applies to the local database.
5. Handlers in `api/internal/httpapi/`, routes wired in `server.go`.
6. Mirror the JSON shape in `web/src/lib/types.ts`, add a call in `web/src/lib/api.ts`.

`sqlc.yaml` overrides `uuid` → `github.com/google/uuid.UUID`, `timestamptz`/`date`
→ `time.Time`, with `emit_pointers_for_null_types`. So nullable columns are Go
pointers (`*string`, `*uuid.UUID`, `*time.Time`) and marshal to JSON `null`
rather than pgtype's wrapper objects. Keep new overrides consistent with this.

Prefer `sqlc.arg('name')` / `sqlc.narg('name')` over `$1` positional params, and
cast them (`sqlc.narg('status')::text`). Mixing named and positional params in
one query produces confusing generated argument ordering.

### Error mapping

Handlers translate Postgres SQLSTATEs into 4xx rather than letting them 500 —
`23505` → 409, `23503` → 400, `23514` → 400. `writeConstraintError` in
`internal/httpapi/employees.go` is the pattern; `pgCode()` in `respond.go`
extracts the code. `writeInternal()` logs the real error and returns a generic
message, so **internal details never reach the client** — keep it that way.

`pgx.ErrNoRows` → 404. Note that sqlc `:execrows` deletes return a row count
instead, so those check `rows == 0`.

### Config

One `.env` at the repo root serves both apps. The Go side loads it via godotenv
(trying `.env`, `../.env`, `../../.env` in order, so it works from either the
repo root or `api/`). The web side reads it because `vite.config.ts` sets
`envDir: '..'`. Adding a var means adding it to `.env.example` too.

`DATABASE_URL` is required — the server refuses to start without it.

## Gotchas

- **Postgres binds host port 5434, not 5432.** Deliberate: Docker Desktop on this
  machine is shared with the ebike stack, whose container owns 5433, and a host
  Postgres already holds 5432. Do not "fix" this back to a lower port.
- `api/internal/db/` is generated. Editing it works until the next
  `./make.ps1 sqlc` silently reverts you.
- `./make.ps1 nuke` and `docker compose down -v` destroy the local volume.
- `hired_on` is a bare `YYYY-MM-DD` date, not a timestamp. The `jsonDate` type in
  `internal/httpapi/respond.go` exists because `time.Time` alone demands full
  RFC 3339 — reuse it for any new `date` column.
- New API areas need CORS to match: the browser origin must be in `CORS_ORIGINS`.
- Svelte 5 runes mode is forced for project files in `vite.config.ts` — use
  `$props()` / `$derived()`, not the Svelte 4 `export let` style.
- The git identity here is set **per-repo** (`Dhananjayan507`), separate from the
  global Tech360 identity. Don't move it to `--global`.
