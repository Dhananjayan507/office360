# office360

Office management platform — Go API + SvelteKit web app on PostgreSQL 16.

| Layer | Stack |
| --- | --- |
| API | Go 1.23 · [chi](https://github.com/go-chi/chi) v5 · [pgx](https://github.com/jackc/pgx) v5 |
| Queries | [sqlc](https://sqlc.dev) — SQL in, type-safe Go out |
| Migrations | [golang-migrate](https://github.com/golang-migrate/migrate) |
| Database | PostgreSQL 16 (Docker) |
| Web | SvelteKit 2 · Svelte 5 (runes) · TypeScript · Vite |

## Layout

```
office360/
├── api/                      Go backend
│   ├── cmd/server/           main() — config, pool, HTTP server, graceful shutdown
│   ├── internal/config/      env loading
│   ├── internal/db/          GENERATED by sqlc — do not edit
│   ├── internal/httpapi/     chi router + handlers
│   ├── db/migrations/        golang-migrate .up/.down pairs
│   ├── db/query/             hand-written SQL, input to sqlc
│   └── sqlc.yaml
├── web/                      SvelteKit 2 frontend
│   └── src/lib/api.ts        typed client for the Go API
├── docker-compose.yml        Postgres 16
├── make.ps1                  task runner (see below)
└── .env.example              copy to .env
```

## Prerequisites

Go 1.23+, Node 20+, Docker Desktop, plus two Go tools:

```bash
go install github.com/sqlc-dev/sqlc/cmd/sqlc@latest
go install -tags 'postgres' github.com/golang-migrate/migrate/v4/cmd/migrate@latest
```

## First run

```bash
cp .env.example .env
```

Then, from the repo root in PowerShell:

```bash
./make.ps1 up
```

```bash
./make.ps1 migrate
```

Start the API (leave it running):

```bash
./make.ps1 api
```

And the web app in a second terminal:

```bash
./make.ps1 web
```

API on <http://localhost:8080>, web on <http://localhost:5173>.

> Postgres binds host port **5434**, not 5432, so this stack coexists with the
> other Postgres instances on this machine. Change `POSTGRES_PORT` in `.env` if
> you prefer.

## Tasks

| Command | Does |
| --- | --- |
| `./make.ps1 up` | Start Postgres, wait for healthy |
| `./make.ps1 down` | Stop Postgres (data preserved) |
| `./make.ps1 nuke` | Stop **and delete the volume** — destroys local data |
| `./make.ps1 migrate` | Apply pending migrations |
| `./make.ps1 rollback` | Roll back the last migration |
| `./make.ps1 sqlc` | Regenerate `api/internal/db` |
| `./make.ps1 api` | Run the Go API |
| `./make.ps1 web` | Run the SvelteKit dev server |
| `./make.ps1 check` | `go build` + `go vet` + `svelte-check` |
| `./make.ps1 psql` | psql shell in the container |

In VS Code these are also wired as tasks — `check: all` is the default build task (Ctrl+Shift+B).

## Changing the data model

The schema is the source of truth for sqlc, so the order matters:

1. Write a new migration pair in `api/db/migrations/` (`000002_thing.up.sql` + `.down.sql`).
2. Add or edit queries in `api/db/query/`.
3. `./make.ps1 sqlc` — regenerates `api/internal/db`.
4. `./make.ps1 migrate` — applies it to your local database.
5. Add handlers in `api/internal/httpapi/` and wire routes in `server.go`.
6. Mirror the JSON shape in `web/src/lib/types.ts` and add a call in `web/src/lib/api.ts`.

Never hand-edit `api/internal/db/` — it is regenerated.

## API

Base path `/api/v1`. Health check at `/healthz` (returns 503 when Postgres is unreachable).

| Method | Path | |
| --- | --- | --- |
| GET | `/employees` | `?department_id=&status=&limit=&offset=` |
| POST | `/employees` | |
| GET | `/employees/{id}` | |
| PATCH | `/employees/{id}` | partial update |
| DELETE | `/employees/{id}` | |
| GET | `/departments` | |
| POST | `/departments` | |
| DELETE | `/departments/{id}` | |

List responses are `{ data, total, limit, offset }`. Errors are `{ error: string }`.
`hired_on` is a bare `YYYY-MM-DD` date; `status` is one of `active`, `on_leave`, `exited`.

```bash
curl -X POST http://localhost:8080/api/v1/employees -H "Content-Type: application/json" -d "{\"full_name\":\"Ada Lovelace\",\"email\":\"ada@office360.dev\"}"
```

## Environment

All config lives in a single root `.env` (gitignored). Vite reads it via `envDir: '..'`,
and the Go API loads it via godotenv. See `.env.example` for the full list.
